# DECISIONS

Decisions taken before development (by the user):
- Translation provider: unofficial Google Translate endpoint (`client=gtx`), no API key.
- Scope: YouTube (dedicated adapter) + generic HTML5 `textTracks`. No Netflix/Prime/Disney.
- Display: configurable — TR only or TR + EN, size/position/background adjustable.
- Stack: TypeScript + Vite, Manifest V3, Chrome + Edge.
- Name: Yerdema Subs (repo `yerdema-subs`). UI languages: Turkish + English.
- Git: local only, frequent commits, no push.

Decisions taken during development (append below, one line each: decision — reason):
- `translate.googleapis.com` (client=gtx) returned HTTP 429 "unusual traffic" to every curl probe from this machine; `clients5.google.com/translate_a/single?client=dict-chrome-ex&dt=t` returned the identical nested-array format — the translator tries the spec endpoint first and falls back to clients5 on 429/non-JSON; both hosts are in `host_permissions`. The fixture `google-sample.json` was captured from clients5 (same shape).
- Google splits the response into sentence segments that do not map 1:1 to input lines — always concatenate all `data[0][i][0]` and then split on `\n` (never map segments to cues).
- The GitHub URL the user mentioned is informational only; per CLAUDE.md no remote is added and nothing is pushed.
- Manifest source lives in `src/manifest.json`; the build injects `version` from `package.json` — single source for the version.
- Popup is built with Vite root `src/popup` → `dist/popup/index.html`; background/content are Vite lib builds (ES / IIFE) via `scripts/build.mjs`.
- `scripts/verify-dist.mjs` runs as part of `npm run build` (not only `package`) so every build is validated.
- Dev deps: TypeScript 7, Vite 8, Vitest 5, jsdom, sharp (icons), fflate (zip), rimraf.
- Persisted per-video cache stores a `text → translation` map (not a positional array) under `vc:<videoKey>` with a timestamp — stays valid if the cue list changes (manual vs ASR track, re-merge) and allows merging partial, priority-ordered results; LRU by timestamp keeps 30 videos.
- `findActiveCue`: start inclusive / end exclusive; for overlapping cues the latest-started still-active cue wins.
- ASR json3 is exploded into word fragments via `tOffsetMs`; overlapping rolling events are clamped (fragment end ≤ next fragment start) before `mergeCues`, otherwise inflated event durations would trigger the 7 s break too early. The 7 s limit is checked on the merged span `max(end) - start`.
- Manual json3 events without `dDurationMs` end at the next event's start (3 s if last). HTML entities in caption text are decoded (`&#39;`, `&amp;`, ...).
- Translation priority window: cues with `end ≥ t-5s` and `start ≤ t+60s` first, then later cues, then earlier ones.
- Translator keeps a sticky "preferred endpoint" (last one that worked); per attempt it tries every endpoint before applying the 1/2/4 s backoff. Non-JSON bodies (the HTML "Sorry" page) count as retryable. Non-429 4xx fail immediately.
- Item-by-item fallback (concurrency 3) runs inside the batch's global slot (max 2 batch slots), so total in-flight requests are bounded.
- Content side sends TRANSLATE messages of ≤ 40 texts each (one Google batch), so a failed batch only affects its own cues; the background also batches defensively.
- Concurrent persisted-cache saves are serialized through a promise chain to avoid read-modify-write races.
- Overlay host is a custom element `<yerdema-subs-overlay>` with an open Shadow DOM (page CSS targeting `div` can't hit it). Settings are applied as CSS variables, so live changes need no re-render.
- Generic mount uses `position: fixed` + `getBoundingClientRect()` updated by ResizeObserver, scroll (capture), resize, `fullscreenchange` and a 1 s safety interval. If the `<video>` element itself is the fullscreen element (native video fullscreen), nothing can be drawn over it (top layer) — known limitation; players that fullscreen a container work.
- Content-side `CueTranslator` drives prioritization: each request takes the next ≤ 40-text batch from `prioritizeCueIndices(currentTime)`, recomputed on every request (so seeks re-prioritize automatically), max 2 requests in flight.
- `sendTranslateMessage` retries an empty response / closed port up to 3 times (MV3 worker may be restarting), gives up immediately on "Extension context invalidated".
- Failed translations keep the English text visible (pending style) and set status `error`; they are retried when the cue list is replaced or the session restarts.
- When `enabled` is false the content script destroys the adapter entirely (no text is sent to Google, track modes/styles restored); re-enabling recreates it.
- GET_STATUS with `all_frames`: frames that contain a `<video>` (and the YouTube top frame) answer immediately, video-less sub-frames stay silent, and a video-less top frame answers after 200 ms — so the popup sees the iframe that actually plays the video.
- Status `detail` is a short code (`turnOnCC`, `noTrack`, `cors`, `loading`, `notPlaying`, `ad`, `translateFailed`); the popup localizes it via `detail_<code>` messages.
- HTML5: before any video has been played the status is `idle` (detail `notPlaying`); videos are found with a debounced (500 ms) rescan of the live `getElementsByTagName('video')` collection on DOM mutations plus capture-phase `play`/`playing` listeners. A playing video is never switched away from.
- HTML5 `videoKey` = `h5:` + FNV-1a hash of origin+path+currentSrc+track language/label (short, stable storage key).
- YouTube embeds in third-party iframes (`youtube.com/embed`) are not handled: the MAIN-world interceptor only runs in the top frame, and the HTML5 adapter never runs on youtube.com.
- Test page video has no `crossorigin` attribute (the MDN host might not send CORS headers); the VTT is same-origin so cues are readable anyway.
- YouTube caption race: the MAIN-world script (document_start) buffers the last json3 payloads for up to 3 videos; the isolated adapter (document_idle) posts `YT_READY` on each video to get them replayed.
- MAIN world ignores timedtext responses that are not json3 (no `"events"`) and auto-translated tracks (`tlang` set). XHR bodies are read only for responseType `''`/`text`/`json`/`arraybuffer`; everything is wrapped in try/catch and the original response is untouched (fetch uses `res.clone()`).
- Payload ranking on the isolated side: manual EN < ASR EN < other-language manual < other-language ASR; a better-ranked payload replaces the current cue list. Non-English tracks are still translated (sl=auto) if nothing English exists.
- `YT_ENABLE_CC` is posted 1.5 s after a video starts if no captions arrived yet or the active track is ASR (to upgrade to manual English). The MAIN world calls `loadModule('captions')`, reads `getOption('captions','tracklist')` (retrying up to 5 s) and `setOption('captions','track', best)`; result is reported back with `YT_CC_RESULT`.
- Status becomes `no-subtitles` (hint "Turn on CC (English)") when enabling CC failed or nothing arrived within 8 s.
- `videoKey` for YouTube = `yt:<videoId>:<lang>` plus `:asr` for auto-generated tracks.
- DOM fallback clears the overlay immediately when the native caption disappears and only debounces (350 ms) new text.
- No `activeTab`/`tabs` permission: the popup uses `chrome.tabs.query` only for the tab id and `chrome.tabs.sendMessage`, which need no permission. Only `storage` is requested.
- Popup slider changes update the UI/preview instantly and are saved debounced (250 ms) to stay within `storage.sync` write quotas; toggles/mode save immediately. Status is re-polled every 1 s while the popup is open.
- Shortcut hint shows the shortcut actually assigned (`chrome.commands.getAll`), or a hint to set one if Chrome/Edge didn't assign Alt+Shift+T (conflicts).
- Failed translations are retried automatically 20 s after a failure (rate-limit recovery), not only on a new cue list.
- Status text keys: `status_<status with - → _>`; an unanswered GET_STATUS shows "This page isn't supported".
- Re-probe at the end of Phase 7: `translate.googleapis.com` gtx still HTTP 429 from this machine; MDN `flower.mp4` test video returns 200.
- Overlay/popup CSS has an explicit `[hidden] { display: none !important; }` — author `display` rules otherwise override the `hidden` attribute.
- Automatic retry of failed translations backs off 20 s → 40 s → 80 s → 160 s → 300 s and then stops (avoids hammering a rate-limited endpoint); a fresh cue list/new video starts over.
- YouTube `hideOriginal` style is only injected while we render a replacement (intercept session or DOM mode), so native captions stay visible when we have nothing to show.
- `enableCaptions` re-selects the best track even if it is already active when nothing was captured for that video yet (forces the player to request it).
- Tabs open before installing the extension must be reloaded (documented in README/MANUAL_TEST) — no programmatic injection, to avoid the `scripting` permission.
- Playwright E2E (`npm run test:e2e`): persistent Chromium context (`channel: 'chromium'`, headless) with `--load-extension=dist`; Google endpoints are mocked via `context.route` by default (deterministic), `E2E_REAL_TRANSLATE=1` uses the real endpoints. With real translation the test page showed "Bu çiçek çok güzel." — the endpoint works from the browser on this machine.
- Stretch "per-site disable": `Settings.disabledSites: string[]` (exact, lower-cased hostnames, max 500). Iframes use the top page's hostname via `location.ancestorOrigins`, so disabling a site also covers its embedded players. GET_STATUS now also returns `host` and the on-screen `current` subtitle.
- Stretch "copy current subtitle": popup copies `translation\noriginal` with `navigator.clipboard.writeText` (allowed in the focused popup, no extra permission).
- Probe from the extension service worker (Playwright Chromium): both `translate.googleapis.com` (gtx) and `clients5.google.com` return HTTP 200 — the 429 seen with curl is client-specific; the fallback stays as a safety net.
- YouTube: `YT_ENABLE_CC` is skipped while an ad is showing and re-sent when the ad ends; a `noPlayer`/`noTracks` result triggers one more attempt after 10 s.
- Real-YouTube smoke test (`e2e/youtube.spec.ts`, gated by `E2E_YOUTUBE=1`): YouTube refuses playback in automated Chromium (headless and headed), so only the player-API caption selection could be verified live (tracklist read, manual EN chosen); interception/overlay on YouTube remain covered by unit tests + manual testing.
